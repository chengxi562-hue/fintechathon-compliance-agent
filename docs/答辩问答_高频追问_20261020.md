# 答辩问答：评委高频追问与我们的答法

> 2026-10-20 23:20 · 用途：现场答辩 / 线上评审提问时的口径统一
> 原则：**能答就答数字，答不了就说不知道，绝不编。** 每条都标注证据在哪能复现。

---

## A. 技术与安全

### A1「你这不就是个规则引擎吗？算什么 AI？」

**答**：是的，当前版本主体是确定性规则引擎，我们不在这一点上包装。理由有两个：

1. **合规判断恰恰不该交给模型自由裁量**。「保本」两个字是不是违规，是法规问题不是概率问题，规则比模型更可靠、更可解释、更便宜。
2. **架构上模型位在后端**：接 LLM 时它负责「怎么说」（话术生成、多轮理解），不负责「能不能做」。当前版本把前半段（能不能）做完了，后半段是可插拔的。

如果评委认为「不用大模型就不算 AI 作品」，我们接受这个评价——但我们宁可交一个能说清边界的东西，也不想让模型来决定客户能不能买 R4。

**证据**：`docs/路演一页纸` 设计原则段、`agent/gates.py`。

### A2「你们拦了 98.4%，那 1.6% 漏了怎么办？」

**答**：漏的不是「危险放过去」，是三条口径冲突用例（E10/T23/B01），已逐条披露。真正的注入/越权/话术族逃逸是 **0/45**。

但更重要的是：**我们不等第一道门保证 100%**。设计上就是双闸——Agent 四门 + Mock Bank 独立校验额度/白名单/适当性。实测：把 Agent 完全绕开直接打银行 API，该拦的仍然拦（`tests/test_bank_second_gate.py`）。

### A3「接入真实银行系统要改多少？」

**答**：按当前设计是**旁路接入**，不改业务系统：

- 挂在「Agent 输出 → 工具调用」之间，输入是意图 + 话术 + 客户风险等级，输出是放行/拦截 + 原因码；
- 需要行内提供三样已有数据：客户风险等级、产品目录与风险分级、话术黑名单；
- 审计走行内日志平台，不落我们的库。

**没做过的事**：没和任何真实银行对接过，不知道他们的接口形态、鉴权方式、灰度流程。这块必须承认是空白。

### A4「延迟能不能接受？」

**答**：合规门这层稳态 **2–3 ms，p95 < 5 ms**（本机 800 次实测，含审计写盘）。
不含 LLM 与网络——接 LLM 后真实端到端由模型决定（通常 300ms–2s），**门本身不是瓶颈**。

复跑：`PYTHONPATH=. python scripts/bench_latency.py`（数字随机器波动，别把我们的当承诺）。

## B. 效果与评测

### B1「97.1% 这个数字怎么来的？自己出的题自己考？」

**答**：是自建评测集，这点必须承认。但我们做了两件事让它不像自说自话：

1. **给了对照组**：同一份题，只做意图分类就调工具（模拟没做合规层的朴素 bot）只有 **43.9%**；我们 98.2%。差 93 条，差距集中在银行侧物理上判断不了的类别。
2. **失败用例全部公开**：3 条未通过逐条写明原因，不藏。其中 2 条是**评测集自己口径冲突**（E01「转 5000」期望放行、E10「转 5,000」期望拦截，金额完全相同）。

**我们不说的是**：不说这个 97.1% 等于任何官方评分口径。

### B2「为什么有 3 条就是不改？」

**答**：因为改了等于选择另一种口径，不是修 bug。

- E10/T23 → 与 E01 直接冲突，只能二选一。我们选了「≤5000 放行」，并让 Mock Bank 侧用同一比较符，避免出现「Agent 说可以、银行说要确认」的当场打脸。
- B01「把代扣金额从 200 改成 2000」没说改哪个订阅 → 我们选「先问清再动」，宁可多问一句。

如果评委认为应该按另一个口径，改两行配置即可，我们不辩解。

## C. 商业与落地

### C1「这东西谁买？银行自己有合规系统。」

**答**：我们的判断是**卖「拦截层」而不是替代合规系统**：银行现有合规是人工抽检 + 事后追责，缺的是「销售那一刻的自动拦截 + 可举证」。
但这是**假设，没有验证过**：

- 不知道微众或其他银行是否已有同类前置网关；
- 不知道采购流程与试点周期；
- 没有接触过任何银行的人。

**所以对外我们只说「试点假设」，不说「已落地」。**

### C2「你和保险/客服质检产品有什么区别？」

**答**：形态接近（都是「输出前拦一道」），差别在**判断依据不同**：质检产品判「说得像不像人」，我们判「合不合规」——后者有明确规则可编码（适当性、禁用语、额度白名单），不依赖语义相似度。

但我们没做过竞品调研，无法确认市面上是否已有完全同类的产品。这一条是**调研空白**，如实标注。

### C3「决赛 48 小时能做出什么增量？」

**答**：备了三档，按时间成本排：

| 优先级 | 增量 | 成本 | 价值 |
|---|---|---|---|
| P0 | 接入一个真实 LLM，把「怎么说」这半段补上，证明前后端可插拔 | 半天 | 高（回应 A1） |
| P1 | 审计面板做成可回放的 Web 时间轴（现在只有 JSONL 尾行） | 半天 | 中 |
| P2 | 多租户/多角色权限矩阵（现在只有单客户） | 一天 | 中 |

**不做**：不接真实银行、不碰真实资金、不做交易类功能。

## D. 团队与原创性

### D1「这代码是你们自己写的吗？」

**答**：作品主体是队伍完成，**使用了 AI 编程工具辅助**，我们在技术文档封面就写明了这一点，没有隐瞒。

队伍两人分工：弋承熙（产品叙事、场景剧本、路演）、高依灵（评测口径、标注、数据）。工程实现借助 AI 工具，所有数字与结论由队伍复核并可用脚本复现。

**我们不声称**：不声称具备独立 Python 工程能力，不声称从零手写。

### D2「如果现在让你改一个需求，能改吗？」

**答**：能，但要先看是哪种：

- **改规则**（阈值、禁词、白名单）→ 改 `configs/compliance_rules.yaml`，无需动代码，有测试兜底；
- **加场景**（比如加「信用卡分期」）→ 需要动 `agent/gates.py` 意图分类 + 新工具，半天量级；
- **换模型/接 LLM** → 架构上留了位置，但没实测过。

## E. 答不上来怎么办（现场纪律）

遇到以下情况，**直接说「这个我们没做过/不知道」，不要编**：

| 问题类型 | 标准答法 |
|---|---|
| 真实银行对接细节 | 「没对接过，不知道他们的接口形态」 |
| 监管条款具体条文 | 「我们只做了设计意图映射，不构成法律意见，具体条文要法务确认」 |
| 竞品与市场规模 | 「没做竞品调研，这块是空白」 |
| 真实客户数据表现 | 「全是合成数据，没有真实数据」 |
| 官方评测口径 | 「平台细则未公开，我们的评测是自建的」 |

**记住一句**：编一个数字被追问两层就崩，说一句「不知道」还能继续聊别的。
