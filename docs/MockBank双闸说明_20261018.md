# Mock Bank 双闸说明（2026-10-18）

W0 P0-2：在 Mock Bank 侧加独立限额/适当性兜底，作为 Agent 四道门之外的**第二道闸**。即使 Agent 合规门被注入/绕过，直接打 bank API 也会被拦。

## 转账 `/v1/transfers`

| 闸 | 阈值 | 行为 |
|---|---|---|
| 白名单硬拦 | `amount > 50_000` | 收款方非客户本人名下账户 → `403 TRANSFER_BANK_WHITELIST_REQUIRED` |
| 日累计软限 | 累计 `> 20_000/日` | 对外（非本人账户）转账累计超限 → `403 TRANSFER_BANK_DAILY_LIMIT_EXCEEDED`；本人名下划转不占限额 |
| 确认软提示 | `amount >= 5_000` 且未 confirmed | 返回 `pending_confirm`（原逻辑，非硬拦） |

## 申购 `/v1/wealth/purchase`

- 适当性兜底：`customer.risk_score < product.min_risk_score` → `403 SUITABILITY_MISMATCH`。
- 例：客户 R2（`cust_yw_001`）申购 R4 产品 `WB_EQ_MIX_003` → 拒绝；申购 R2 `WB_BOND_002` → 放行。

## 实现位置

- `mock_bank/app.py`：常量 `DAILY_SOFT_LIMIT_CNY` / `WHITELIST_ONLY_ABOVE_CNY`，辅助 `_is_whitelisted_recipient` / `_daily_posted_total`，检查内联在两个端点内。
- 阈值与 `configs/compliance_rules.yaml` 的 `transfer.*` / `suitability.min_risk_score_by_product` 保持一致（W0 为硬编码镜像；W1+ 可考虑共享加载，避免双写漂移）。
- 白名单定义：客户本人名下账户（行内同名划转）。demo 无日期维度，日累计按内存中全部 `posted` 转账计。
